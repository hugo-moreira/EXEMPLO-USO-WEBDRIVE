O QUE VOCÊ VAI APRENDER

ARRANGE

Prepara

Cria o driver do Chrome e abre a URL. No fim desta fase a tela de login está no navegador e nenhum campo foi preenchido.

build() devolve um ThenableWebDriver: dá para chamar get() sem await no build. Await no build deixa explícito o momento em que a sessão falhou ao abrir.

PRODUZ

Chrome aberto em quick-notes.club, com o formulário ainda vazio.

ACT

Age

Localiza #login-email e #login-password, digita e manda Enter. É o gesto da pessoa usuária. O teste ainda não decide se o login deu certo.

sendKeys aceita texto e teclas na mesma chamada. A senha e Key.RETURN vão juntos no segundo campo.

PRODUZ

O formulário foi enviado. O teste ainda não sabe se a conta entrou.

ASSERT

Confere

Espera a saudação, lê #user-name e compara com o texto esperado. assert.equal falha com a diferença exata entre o recebido e o esperado.

quit() fecha o Chrome. No arquivo atual ele está depois do assert, então uma falha pula o fechamento.

PRODUZ

Teste verde quando o texto de #user-name é o esperado. Teste vermelho com os dois textos na mensagem.

CAPÍTULO 5

Quando o teste
de login falha

Quatro falhas cobrem quase todo erro deste arquivo: o Mocha desiste em 2 segundos, o elemento não está lá, o texto mudou, ou o Chrome fica aberto depois do erro.

O QUE VOCÊ VAI APRENDER

  • Separar o prazo do Mocha do prazo do Selenium.
  • Ler NoSuchElementError e TimeoutError.
  • Usar a diferença do assert para achar texto trocado.
  • Fechar o navegador também no caminho de erro.
1. O Mocha corta aos 2 segundos

O prazo padrão do Mocha é 2000 ms. Abrir o Chrome e esperar a saudação passa disso. O it deste arquivo é uma arrow function, então this.timeout() dentro dele não altera o caso. O prazo vale no describe, que já é uma function comum.

Timeout of 2000ms exceeded
AÇÃO

this.timeout(20000) no describe. O it pode continuar como function, para o this do Mocha existir.

2. O campo ou a saudação não existe

findElement rejeita assim que a busca única falha. By.id vira CSS. Confira se a URL é a tela de login e se o id continua no HTML.

no such element: *[id="user-name"]
AÇÃO

Troque a busca da saudação por elementLocated. Confira os ids do formulário no HTML da página.

3. A saudação veio diferente

O elemento apareceu, o texto não é o esperado. assert.equal mostra os dois lados. Atualize LOGIN_GREETING ou corrija a conta usada no teste.

Expected values to be strictly equal
AÇÃO

Leia o texto que a página mostrou e alinhe LOGIN_GREETING a ele.

4. O Chrome continua aberto

quit() está depois do assert. Qualquer throw anterior pula essa linha e deixa o processo do navegador vivo. O finally do capítulo 6 roda nos dois caminhos.

processo chrome ainda listado
AÇÃO

Feche o Chrome que sobrou e rode de novo com quit() dentro de finally.

import assert from 'node:assert/strict';
import { Builder, Browser, By, Key, until } from 'selenium-webdriver';

const URL = process.env.APP_URL ?? 'https://quick-notes.club/';
const EMAIL = process.env.LOGIN_EMAIL;
const SENHA = process.env.LOGIN_PASSWORD;
const SAUDACAO = process.env.LOGIN_GREETING;

describe('Testes do Módulo de Login', function () {
  this.timeout(20000);

  it('permite o login com credenciais válidas', async function () {
    if (!EMAIL || !SENHA || !SAUDACAO) {
      throw new Error('Defina LOGIN_EMAIL, LOGIN_PASSWORD e LOGIN_GREETING.');
    }
    const driver = await new Builder().forBrowser(Browser.CHROME).build();
    try {
      await driver.get(URL);
      await driver.findElement(By.id('login-email')).sendKeys(EMAIL);
      await driver.findElement(By.id('login-password')).sendKeys(SENHA, Key.RETURN);
      const nome = await driver.wait(until.elementLocated(By.id('user-name')), 8000);
      await driver.wait(until.elementIsVisible(nome), 8000);
      assert.equal(await nome.getText(), SAUDACAO);
    } finally {
      await driver.quit();
    }
  });
});
